# Pull Request：把修改交给项目 review

## PR 不是 Git 命令

Pull Request（PR）是 GitHub 等平台提供的协作功能：你把自己的分支推送到远程仓库，请求维护者把它合入目标分支。Git 本身没有 `git pr` 这样的命令。

典型流程：

```text
Fork → Clone → Branch → Commit → Push → Open PR → Review → Merge
```

## 第一步：Fork 仓库

在 GitHub 打开项目页面，点击右上角 **Fork**，得到一份属于你的副本：

```text
https://github.com/你的用户名/git-practice-07
```

Fork 之后，你的副本和原仓库是两个远程仓库。原仓库通常叫 `upstream`，你的副本叫 `origin`。

## 第二步：克隆并配置远程

```bash
git clone https://github.com/你的用户名/git-practice-07.git
cd git-practice-07

git remote -v
git remote add upstream https://github.com/hdlumi/git-practice-07.git
```

检查：

```bash
git remote -v
# origin    https://github.com/你的用户名/git-practice-07.git (fetch/push)
# upstream  https://github.com/hdlumi/git-practice-07.git (fetch)
```

## 第三步：从最新 dev 创建分支

```bash
git fetch upstream
git switch -c docs/my-contribution upstream/dev
```

不要直接在 `main` 上改。一个 PR 只解决一个问题，分支名要能看出意图。

## 第四步：修改、提交、推送

```bash
# 修改文件后
git status
git diff
git add 修改的文件
git commit -m "docs: 补充我遇到的 Git 问题"

git push -u origin docs/my-contribution
```

推送后，GitHub 通常会在仓库页面显示 **Compare & pull request** 按钮。

## 第五步：写清楚 PR 描述

一个好的 PR 描述包含：

- **改了什么**：一句话说明范围
- **为什么改**：关联 Issue，例如 `Closes #12`
- **怎么验证**：运行了哪些命令，结果如何
- **截图**：涉及界面或文档排版时附上

示例：

```markdown
## 改了什么
补充 Windows 终端中文乱码的排查步骤。

## 为什么改
Closes #12，有同学在 Windows 下运行 check 时看到乱码。

## 怎么验证
- 在 Windows 11 + PowerShell 7 下按文档执行
- `python -m gitpractice check` 通过
```

## 第六步：回应 review

维护者可能要求改措辞、补测试或拆分提交。继续在同一个分支提交并推送即可，PR 会自动更新：

```bash
git add .
git commit -m "docs: 根据 review 补充 chcp 示例"
git push
```

不要为了“看起来干净”而强推（force push）正在 review 的分支，除非你确认没有其他人基于它工作。

## 第七步：合并后同步

PR 合并后，可以删除远程分支，并同步本地：

```bash
git switch dev
git pull upstream dev
git branch -d docs/my-contribution
git push origin --delete docs/my-contribution
```

## 练习：提交一个文档改进

1. Fork 本项目。
2. 找一处可以更清楚的中文说明，或补充一个你踩过的坑。
3. 从 `upstream/dev` 创建 `docs/你的名字-改进` 分支。
4. 提交并 push。
5. 打开 PR，写清楚改了什么、为什么改、怎么验证。
6. 把 PR 链接回复到课程 Issue 中。

## 验收标准

- PR 的目标分支是 `dev`，不是 `main`
- 分支只包含一个主题的修改
- PR 描述包含关联 Issue 和验证方式
- 没有把 `.venv/`、`__pycache__/` 等无关文件提交进去
- 能解释 Fork 和 clone 的区别
